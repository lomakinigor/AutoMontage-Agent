# AutoMontage-Agent v1.5.0: public batch-Reels release specification

## Goal

Publish AutoMontage-Agent v1.5.0 as a reproducible public package that teaches an
agent how to edit one talking-head Reel or a batch of Reels without publishing client
media, biometric data, transcripts, local paths, private branding, licensed music,
render logs, or client-specific QA evidence.

## Product contract

- Node.js 20+, local faster-whisper, Remotion and FFmpeg remain the supported stack.
- A clean clone must install, pass tests, render the neutral demo and expose only the
  commands documented by node scripts/cli.js --help.
- Batch editing is an agent workflow over existing commands, not a new
  automontage batch command in v1.5.0.
- Each output version owns a separate ignored projects/<id>/ workspace.
- Hook variants share one approved body; only the hook splice and hook-specific cover differ.
- Draft previews may be generated autonomously, but approved finals retain the existing
  explicit approval gate.
- The official scenes remain fullscreen, split, bottom-diagram, blur-overlay, text-only,
  stat, and broll.
- Content-specific Remotion animation may be rendered inside an ignored project and
  imported as muted broll; it does not create an eighth public scene type.

## Editorial contract

- Default target: vertical talking-head Reels up to two or three minutes.
- Preserve natural speech. Remove only clear silence, abandoned false starts and verified
  repeats. When a cut is ambiguous, keep it.
- Target a meaningful visual event every two to three seconds.
- Keep the speaker visible during the first two or three seconds. Text and logos may
  overlay a live or blurred speaker; a text-only opening is not allowed.
- Apply subtle continuous speaker motion, normally a one-to-four-percent push or pull.
- Add three to five semantic visualizations to a two-to-three-minute Reel when supported
  by the speech.
- Process diagrams animate block by block: node, connector, next node, result.
- Lists appear as readable cards, lanes or grouped statements rather than small bullets.
- Comparable metrics share one scale and identify the winner in the same frame.
- Full-screen vector explanations suppress ordinary captions and conflicting overlays.
- Captions are mandatory elsewhere and stay inside safe zones.
- Music is modern, licensed, quiet under speech and controlled by sidechain ducking.
- Covers are produced locally per output: recognizable speaker, one short promise and
  one visual metaphor. Official logos require redistribution provenance.

## Batch contract

- Inventory all source files and expected outputs before transcription.
- Normalize names only inside ignored project workspaces; never publish source names.
- Analysis, transcription and asset preparation may run concurrently.
- Full Remotion renders on one checkout run serially; concurrent builds require separate
  worktrees.
- A local batch index records project id, source fingerprint, hook family, approval state,
  preview path, final path and QA state.
- One combined review package may approve all versions. A rejected item returns only that
  item to draft unless the shared body changed.
- Hook-family QA verifies that each post-hook body is identical in speech, scene timing,
  graphics, music and captions.

## Public privacy contract

Allowed in Git:

- source code, schemas and tests;
- generic documentation and placeholder paths;
- deterministic synthetic fixtures;
- binary assets listed in ASSETS.md with origin and redistribution basis;
- generic acceptance criteria and non-client-specific examples.

Forbidden in Git:

- client source, preview or final video and audio;
- faces, voice samples, covers, contact sheets or extracted client frames;
- client transcripts, scripts, filenames, topics, timings or hashes;
- private themes, brand palettes and personal design screenshots;
- licensed music files or undocumented third-party logos;
- absolute home, Downloads, Desktop or temporary-system paths;
- environment files, credentials, browser exports, logs and local memory;
- manifests and QA reports tied to real client projects.

The privacy gate reads Git's index in staged mode, inspects all tracked paths in CI,
rejects forbidden roots and personal absolute paths, and allows tracked media only when
recorded in ASSETS.md. Gitleaks remains a separate secrets gate.

## Release contract

- The release branch starts from current origin/main in a clean worktree.
- Version is 1.5.0 in package.json and package-lock.json.
- Living documentation and the reel skill stay synchronized with behavior.
- The current moderate node-vibrant transitive advisory is re-reviewed for 1.5.0.
  No forced downgrade or incompatible override is allowed.
- CI, Gitleaks, privacy checks, release hygiene, tests and clean-clone demo all pass
  before tag creation.
- Remote push, merge, tag and GitHub Release require explicit publication approval and
  never use force push.
- Cached GitHub references and external forks from earlier history are handled privately
  outside the public repository.

## Acceptance criteria

1. A clean clone passes npm ci, npm test, npm run check:release,
   npm run check:privacy, npm run demo and npm pack --dry-run.
2. No tracked file contains a personal absolute path or client workspace artifact.
3. Every tracked media file appears in ASSETS.md and is visually neutral.
4. Public demo transcript, captions and legacy props are deterministic synthetic data.
5. Documentation describes single-Reel and batch workflows without inventing a CLI.
6. Hook families, vector explainers, captions, sidechain music, covers and batch QA have
   explicit, testable rules.
7. The v1.5.0 tag points to the exact green commit used for the GitHub Release.
